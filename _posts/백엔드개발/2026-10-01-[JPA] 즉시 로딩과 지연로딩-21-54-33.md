## FetchType 정리

>JPA에서 `FetchType`은 엔터티를 조회할 때 연관된 다른 엔터티를 
>어떻게 가져올지 결정하는 로딩전략 설정 옵션
>성능 최적화와 관련이 깊고, 연관된 엔터티를 로딩하는 시점을 결정

### 1. FetchType.Lazy | 지연로딩

- 연관된 엔터티를 **실제 사용할 때 조회**
- 처음 조회 시에는 실체 객체 대신 **프록시(Proxy)객체를 생성 및 반환**
- 불필요한 데이터 조회를 막아 성능 향상 가능
- 기본값 : `@OneToMany` , `@ManyToMany`

#### 예제
```java
@Entity
@Table(name = "tb_user")
public class UserEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "user_sq")
    private Long userSq;

    @Column(name = "user_nm")
    private String userNm;

    // 지연 로딩 (FetchType.LAZY)
    // User 조회 시 orders는 조회하지 않고 프록시(Proxy) 객체로 대치
    // 실제 user.getOrders().get(...) 등으로 데이터 접근 시점에 SQL 실행
    @OneToMany(fetch = FetchType.LAZY, mappedBy = "userInfo")
    private List<OrderEntity> orders = new ArrayList<>();
}
```

### 2. FetchType.Eager | 즉시로딩

- 조회할 A엔터티와 연관된 B 엔터티를 **함께 한번에(즉시) 조회**
- 한번에 필요한 모든 데이터를 가져올 수 있음
- 필요하지 않은 데이터까지 조회되어 성능 이슈 발생할수도
- 보통 `JOIN`쿼리를 사용해 데이터를 즉시 가져옴
- 예상치 못한 조인 쿼리가 발생하거나 N+1 문제를 일으킬 수 있음
- 기본값 : `@OneToOne` , `@ManyToOne`

#### 예제
```java
@Entity
@Table(name = "tb_order")
public class OrderEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "order_sq")
    private Long orderSq;

    @Column(name = "order_nm")
    private String orderNm;

    // 즉시 로딩: Order 조회 시 tb_user 테이블도 JOIN하여 한 번에 가져옴
    @ManyToOne(fetch = FetchType.EAGER)
    @JoinColumn(name = "user_sq")
    private UserEntity userInfo;
}
```
